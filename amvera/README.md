# Утренний выпуск Horizon

Рабочая ветка — `main`. Контейнер собирает новости с 07:30 по Москве за предыдущие 24 часа и отправляет выпуск в 08:00. При позднем старте догоняет сегодняшний выпуск. Ленты и каналы заданы в [feeds.json](feeds.json).

## Подключение личного аккаунта

1. В проекте Amvera `horizon` (Miami-0) задайте секрет `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` проверенного чата. Секреты GitHub Actions доступны только внутри соответствующего запуска Actions.
2. На устройстве с браузером запустите из каталога Horizon `HORIZON_CHATGPT_AUTH_DIR="$HOME/.config/horizon/amvera-login" uv run horizon-chatgpt login --enable-plan`. Подтвердите право Horizon использовать подписку в окне OpenAI. Подробности описаны в [руководстве Horizon](../docs/chatgpt.md) и [процедуре OpenAI для собственного сервера](https://developers.openai.com/siwc/token-sharing-open-source/self-hosted-vms).
3. Контейнер при первом старте создаёт собственный `/data/chatgpt/host.json`. Передайте **только** локальный `~/.config/horizon/amvera-login/credentials.json` через защищённый канал в `/data/chatgpt/credentials.json` этого проекта. В кабинете Amvera для файлов постоянного тома используется «Репозиторий → Data». Перезапустите контейнер после импорта. Сессией и обновлением токена с этого момента управляет сервер.
4. Для разовой проверки выполните в контейнере из `/app` команду `/app/.venv/bin/python -m amvera.worker --check`. Она проверяет реальный ответ модели, бота и выбранный чат. Подтверждение фактической отправки выпуска появится отдельно как `sent`.
5. Если раньше расписание было приостановлено через `RADAR_ENABLE_SCHEDULE=0`, установите `1`. Без переменной расписание включено. `HORIZON_CHATGPT_MODEL` позволяет выбрать модель из каталога подписки. По умолчанию используется первая доступная в порядке OpenAI.

## Доставка и состояние

`GET /health` возвращает состояние без учётных данных. `prepared` означает, что текст готов к отправке. `sent` означает, что Telegram вернул идентификатор сообщения для выбранного чата. При подтверждённом отказе Telegram выпуск ждёт повторной отправки. Если соединение пропало после передачи запроса, состояние меняется на `delivery_unconfirmed`. В этом случае проверьте чат за указанную дату. Автоматический повтор мог бы продублировать уже принятый выпуск. Текст и квитанция хранятся в `/data/radar/editions.sqlite3`.

Права на каталоги авторизации и состояния — `0700`, на файлы авторизации — `0600`. Токены обновляются под файловой блокировкой. После отзыва сессии потребуется повторное подтверждение аккаунта. Клиент использует только провайдер `openai-chatgpt`.
